## Что сработало

Единственный источник всех 0.0012 прибавки — использование лидерборда как
**измерительного прибора**, а не оракула «да/нет». Каждая отправка с известным
счётом даёт уравнение на скалярное произведение истины с этим вектором;
неизвестная `<y,y>` сокращается при `Sum w = 1`:

```
MSE(w) = w'Gw − Sum wi*Gii + Sum wi*MSEi
```

Оптимум считается в замкнутой форме **без новых отправок** (`src/lb_combine.py`).
Метод предсказал собственный счёт трижды: расхождения +2.9e-06, +2.6e-05, −5.0e-06.

**Дисциплина обязательна.** Норма весов ≤ 5, отрицательных прогнозов не
допускать (обрезка выводит из аффинной оболочки и лишает предсказание точности).
Без ограничения перебор выдаёт веса ±6288 и «счёт» 1.637 — эксплуатацию почти
вырожденных направлений, которая на закрытой части развалится.

## Что не сработало

Тринадцать раундов внешнего аудита, свыше шестидесяти проверенных гипотез. Все
находки уложились в 0.000002 … 0.00013 при нужных 0.0012, и ни одна не пережила
переноса между временными окнами.

**Закономерность без единого исключения: внутри окна структура есть почти всегда,
между окнами не переносится почти никогда.** Причём выразительность метода
подгонки обратно пропорциональна качеству переноса — три линейных веса
переносятся, дерево на пятнадцати входах нет, даже с семью листьями и L2 = 200.

Закрыто прямыми измерениями:

- **Модели.** Пять классов оценщиков (LightGBM, CatBoost, двухчастная,
  свёрточная сеть, многоклассовый классификатор по бинам `log1p`) — корреляция
  остатков 0.9966…0.9989. Модель на сырой траектории без агрегатов: корреляция
  0.990 (ниже всех), вклад в ансамбль +0.00009. Стекинг хуже линейной смеси.
- **Признаки.** Три волны инженерии, BTYD, «год назад», логарифмы 30-дневных
  блоков, энтропия по дням недели, корреляция с глобальным рядом, история
  пропусков, произведения топ-признаков. Регуляризованная регрессия на остаток
  даёт +0.002 внутри якоря и не переносится.
- **Посттрансформации прогноза.** Множитель (оптимален, проверен тремя
  отправками: вершина параболы 0.96649 против использованных 0.9664), сдвиг
  логарифма, наклон, пол, потолок, изотоническая, подецильная, погрупповая,
  квантильная, калибровка по неуверенности — все от 0 до отрицательных.
- **Обучающая выборка.** Плотность якорей, число итераций (1024 хуже 512 с
  t = −4.27), усреднение сидов, фильтр по правилу отбора организаторов.
- **Артефакты данных.** `user_id` и порядок строк пусты; `user_id mod K`
  объясняет ровно `K/n` — то есть ровно столько, сколько случайная группировка.
  Ценовой решётки нет (все 4.7 млн положительных значений различны), задержки
  заказ→деньги нет, внутридневного порядка событий нет (`event_date` это Date,
  и пар «пользователь-день» ровно столько же, сколько строк).
- **Постановка.** Взвешенная метрика опровергнута: взвешивание меняет RMSLE на
  десятые доли, а наши предсказания счёта из невзвешенной формулы сбылись с
  точностью 1e-05.

**Аудит кода** дефектов, влияющих на метрику, не нашёл: утечки нет (418 из 418
колонок воспроизведены из усечённых по якорю данных), окна ровно 30 дней, порядок
пользователей идентичен, тензор сети индексируется верно, калибровка применяется
однократно.

## Почему предел информационный

Половина пользователей за 30 дней не тратит ничего, и это по существу
подбрасывание монеты. Персональный остаток модели между непересекающимися окнами
коррелирует на **0.011** — то есть ошибка почти целиком событийная, а не
свойство пользователя. Такое не переносится по определению, и никакая архитектура
этого не меняет: пять разных оценщиков воспроизводят один и тот же остаток.

## Ошибки, которые стоит помнить

**Привязка счёта к файлу — дважды, и оба раза дорого.**

1. Счёт 1.6493157 принят за `submission_v9.csv`, а принадлежал `v9_opt`. Двое
   суток выводов на неверной базе, включая ложное «мы в локальном оптимуме».
2. Резервной копии старого `submission.csv` приписан счёт 1.6548554 — оптимум
   подскочил до 1.6443592, выше лидера. Git показал две версии файла от 27.08 с
   отношением сумм ровно 1.1430 (множитель из README), что опознало копию как
   соответствующую счёту 1.6505943. Отправка «оптимума» с весом −1.87 на неверно
   привязанном векторе дала бы ~1.6524.

**Правило: сверять привязку счёта к файлу явно, до расчёта.**

Прочие:

- «Отсутствует 12% теста» — подставлена доля неактивных обучающего пула вместо
  тестового. Верно 2–3%, вклад в ошибку 1.5%.
- «Два чистых якоря» 2025-09-29 и 2025-10-13 **не независимы**: целевые окна
  пересекаются на 16 днях из 30. Это породило ложный «перенос» поправки на
  остаток (+0.0007), давший на борде минус.
- «В признаках пусто» — вывод из переобученного фита с отрицательным R². При
  нормальной регуляризации там +0.002. Вывод оказался верным по неверной причине.
- Отрицательные результаты систематически отчитывались как установленные, без
  парных интервалов и доверительных границ.

**Обусловливание на исходе** — источник почти всех ложных находок. Разбиение по
фактическому значению цели даёт остатки от −1.21 до +1.85, что выглядит как
катастрофическое смещение; разбиение по прогнозу даёт от −0.03 до +0.07. Первое
воспроизводится и у идеально откалиброванной модели.
